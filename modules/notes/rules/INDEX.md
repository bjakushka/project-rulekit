## Notes: retained project knowledge

`notes/` holds project-specific context worth preserving but not yet belonging
to a more specific project artifact. Use it for investigations, inventories,
reference material, and the reasoning behind decisions.

- Keep one focused topic per Markdown file with a descriptive name
- Record the source or date when it affects how the note should be trusted
- Say explicitly when a conclusion is tentative, historical, or superseded
- Preserve enough evidence and reasoning to understand the note without its
  original conversation
- Notes describe context; they do not define assistant behavior. Put behavior
  rules in rule modules
- Do not use notes as an inbox, backlog, or execution plan. Move actionable
  work to the corresponding system with the owner's approval
- When no dedicated decision module is selected, a note may preserve a
  decision and its rationale. Mark whether that decision is still current
